# 地址与实现

本文记录 Panasonic DC-S5 一代（MC801）固件 2.9 的实机观察与当前实现。代码入口使用 Thumb-2。表中的多字节数值按小端读取。部署脚本使用临时服务模式 USB `04DA:2370`，通过 WinUSB 与机身通信。

## 固件入口

| 地址 | 已验证用途 |
| --- | --- |
| `0x866B1244` | 调度入口，机身上约 61 Hz。原始字节 `2de9fc41`，即 `push.w {r2-r8, lr}`。部署后为 `bef4dcbe`，跳到 `0x86370000` |
| `0x866B1248` | 调度原始函数续接点。负载恢复现场并执行原始入栈指令后跳回这里 |
| `0x866B16B8` | 固件设置发布入口。Fn2 切换、退出及 ISO 应用回传后的补发都通过它请求原生设置发布 |
| `0x86805A04` | 主设置包构建例程 |
| `0x86805A4C` | 从 `[r5 + 0xA84]` 读出闪光模式。原始字节 `95f8840a`，部署后为 `6df798b5`，跳到 `0x86373580` |
| `0x86805A50` | 原始 `strb r0, [r4, #4]`。覆盖负载返回到此处，由原固件写入模式字节 |
| `0x86805B06`、`0x86805B0A` | 读取本次 ISO 档位并写入设置包 `+0x19` |
| `0x86410026` | 固件的指令缓存失效例程。调度入口每次安装或移除时由负载调用 |
| `0x867833E6` | 早期实验的差分同步入口，约 4.4 Hz。现版部署仅比对原始字节 `2de9f041`，用于识别仍在运行的旧补丁 |

| `0x08AA819C` | u16 | 短时快门脉冲。半按位为 `0x0001`，全按位为 `0x0100`。两位可以分别检查 |
| `0x08AA81A2` | u16 | 光圈拨轮档位观察值。单独拨光圈时实测变化，设置包钩子用其变化识别调整 |
| `0x08AA81A4` | u16 | 快门速度拨轮档位观察值。单独拨快门速度时实测变化 |
| `0x08CC1930`、`0x08CC1936` | u16 | 实机观测的光圈、快门速度相关设置量，分别在单独调整时变化。当前钩子使用前两行的拨轮档位 |
| `0x08CC1824`、`0x08CB1B5C` | u16 | 闪光命令的两份副本。强制关闭 `0x0105`，强制开启 `0x0106`，强制开启／防红眼 `0x010F` |

| `0x08CC867A`、`0x08AC7FC1` | u8 | 本次发送的 ISO 档位与上一包序列化的档位。发送端从 `(*(sl + 0x484)) + 0x18A` 读取，实测绝对地址为 `0x08CC867A`。包内位置为 `+0x19` |
| `0x08AC8F34` | 标志 | 设置邮箱的待处理标志。状态机等待 bit 0 清除 |
| `0x08B44356`、`0x08B4436C` | u8、u16 | 应用后的闪光使能与 ISO 数值。程序用它们判断环境光预览生效及 ISO 更新回传 |
| `0x08AC8BC2`、`0x08AC8BD8` | u16 | 机身回传的应用态副本，可观测闪光使能与 ISO |
| `0x08CA8182`、`0x08CB8936` | u16 | 主设置区的闪光使能副本。开为 `1`，关为 `0`。属于应用状态 |
| `0x08CA8198`、`0x08CC1944`、`0x08CC1DA4` | u16 | 主程序中已应用 ISO 的观测副本，可用于调试回读 |
| `0x08CA818C`、`0x08CB8940` | u16 | 同步速度上限的派生副本。实测 `0x0800` 对应约 1/250，`0x0D00` 对应约 1/8000 |
| `0x08AA81A6` | u16 | 随菜单或调节项变化的 UI 镜像。历史试验中曾随闪光模式和 ISO 变化，当前实现通过专用字段判断模式与曝光参数 |

实机试验中，单独改写应用态使能或同步上限会被固件覆盖。持续把出包模式压成 `05` 会得到实时预览，但半按或全按后才恢复也会遇到首张不闪。只改共享缓冲里的模式字节同样未能可靠引闪。当前实现保留两份闪光命令，让固件在进入快门流程前有机会发布自己的闪光设置。

## 预览状态机

| `Preview` | 实现 |
| --- | --- |
| `0` 普通取景 | 设置包沿用固件模式。Fn2 按下边沿转入 `1`，调用固件设置发布 |
| `1` 等待环境光应用 | 对强制闪光 `06` 和防红眼 `0F` 的主设置包覆盖模式为 `05`。Fn2 松开后，收集 15 个符合条件的调度采样，再进入 `2`。条件为应用态闪光关闭、出包模式为 `05`、邮箱待处理位已清除 |
| `2` 环境光已应用 | 普通设置发布沿用原模式。识别到光圈、快门速度或 ISO 档位变化时，仅覆盖该次发布和随后约 0.2 秒内的重复包。已经应用的 ISO 数值发生变化时，调度负载另有一次补发路径 |

设置包钩子只处理已确认的主设置包和两种闪光模式。它先检查快门脉冲，有脉冲时沿用固件原模式。调度负载看到半按或全按会退出预览并请求原生发布。若漏采到短脉冲，连续 12 个调度周期看到闪光使能恢复也会退出。再次点按 Fn2 可以主动退出。

ISO 变化的判定发生在旧包的档位字节被覆盖前。检测到任一档位变化后记录当前调度计数。12 个调度 tick 的窗口涵盖一次拨轮操作引起的重复发布。ISO 51200 到顶后继续向上拨，机身可能仍发布设置包，但 ISO 档位不变。这类发布仍会退出预览。

### 安装和移除顺序

主机先核对原始入口，写入三段负载并回读。设置包入口以安全过渡指令切换两个半字。之后，主机提交安装请求，下一次固件设置发布调用安装负载。负载使用单次对齐的 32 位存储更新调度入口并刷新指令缓存。部署程序最后确认跳转字节正确且调度计数增长。

移除时先让机身通过同一安装负载恢复调度入口，再恢复设置包入口。整个过程使用易失 RAM。早期实验直接分两次写调度入口，曾出现 USB 掉线或回读正常但钩子未运行，因而现版用机身内的单次指令写入。

## 验证记录

2026-11-26 在 DC-S5 一代 FW 2.9 上使用神牛 Godox iT32，以「强制闪光开」完成实机测试。该组合的闪光模式菜单只提供「强制闪光开」「强制闪光开/红眼降低」「强制闪光关」。其余两种模式未能实测，使用时可能出现预览或引闪异常。测试所用的「始终显示预览」选项见 [相机设置](../USAGE.md#相机设置)。

- 点按 Fn2 后，画面持续保持实时预览。
- 在有效 ISO 档位间调整，实时预览保持。到 ISO 51200 后继续向上拨会退出。
- 分别调整光圈和快门速度，实时预览保持。调整后半按再全按，外接闪光灯引闪。
- 迭代实测从实时预览直接全按可引闪。最终版本复测了半按再全按及曝光参数调整后的引闪。
- 三段发布负载已与机身 RAM 回读逐字节比对。「强制闪光开/红眼降低」通过了设置包和恢复路径仿真，当前版本的该模式实机表现待复测。
